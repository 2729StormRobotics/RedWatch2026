# AdvantageKit Logging Setup

This document describes how AdvantageKit logging is set up in this robot codebase and how to use it properly.

## Overview

AdvantageKit provides comprehensive logging capabilities for FRC robots, including:
- Automatic input logging via `@AutoLog` annotation
- Output logging via `Logger.recordOutput()`
- Replay capabilities for testing
- NetworkTables integration

## Current Logging Setup

### Robot.java
- Extends `LoggedRobot` instead of `TimedRobot`
- Sets up data receivers based on mode (REAL, SIM, REPLAY)
- Records build metadata (Git SHA, build date, etc.)
- Starts the logger in `robotInit()`

### Subsystem Logging Pattern

All subsystems follow this pattern:

1. **IO Interface** (`*IO.java`)
   - Contains `@AutoLog` annotated `*IOInputs` class
   - Defines methods for hardware interaction
   - Example: `SampleMotorIO.java`

2. **IO Implementations**
   - Real hardware: `*IOReal.java` (e.g., `SampleMotorIOReal.java`)
   - Simulation: `*IOSim.java` (e.g., `SampleMotorIOSim.java`)
   - Replay: Empty implementation `new IO() {}`

3. **Subsystem Class** (`*.java`)
   - Creates `*IOInputsAutoLogged` instance (auto-generated by annotation processor)
   - Calls `io.updateInputs(inputs)` in `periodic()`
   - Calls `Logger.processInputs("SubsystemName", inputs)` to log inputs
   - Uses `Logger.recordOutput()` for outputs
   - Uses `@AutoLogOutput` annotation for getter methods

## Example: SampleMotor Subsystem

The `SampleMotor` subsystem demonstrates proper logging:

### Inputs (Auto-logged)
- Position (rotations)
- Velocity (rotations/sec)
- Applied voltage
- Current draw
- Temperature

### Outputs (Manually logged)
- Desired voltage
- Desired percent output

### Usage
```java
// In RobotContainer
sampleMotor = new SampleMotor(new SampleMotorIOReal()); // Real hardware
sampleMotor = new SampleMotor(new SampleMotorIOSim());  // Simulation
sampleMotor = new SampleMotor(new SampleMotorIO() {});  // Replay

// In commands
sampleMotor.setPercent(0.5);  // Run at 50%
sampleMotor.setVoltage(6.0);   // Run at 6V
sampleMotor.stop();             // Stop motor
```

## Logging Best Practices

1. **Always use `@AutoLog` for inputs**
   - All sensor readings, motor states, etc. should be in the `*IOInputs` class
   - The annotation processor automatically generates logging code

2. **Use `Logger.processInputs()` in periodic**
   - Call this once per subsystem per cycle
   - Use a consistent naming scheme: `"SubsystemName"` or `"SubsystemName/ComponentName"`

3. **Log outputs explicitly**
   - Use `Logger.recordOutput()` for setpoints, desired states, etc.
   - Use `@AutoLogOutput` annotation on getter methods

4. **Use consistent naming**
   - Inputs: `"SubsystemName/InputName"`
   - Outputs: `"SubsystemName/OutputName"`
   - Use forward slashes for hierarchy

5. **Log at appropriate frequencies**
   - High-frequency data (odometry): Use separate threads
   - Normal data: Log in `periodic()` (50Hz)

## Viewing Logs

1. **During runtime**: Use AdvantageScope or NetworkTables
2. **After match**: Logs are saved to `/U/logs` on the roboRIO
3. **Replay**: Use AdvantageScope to replay logs

## Adding New Subsystems

When adding a new subsystem:

1. Create `*IO.java` interface with `@AutoLog` inputs
2. Create `*IOReal.java` for real hardware
3. Create `*IOSim.java` for simulation
4. Create `*.java` subsystem class
5. Add to `RobotContainer` with proper mode switching
6. Call `Logger.processInputs()` in `periodic()`

See `SampleMotor` subsystem for a complete example.
